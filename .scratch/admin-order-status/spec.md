# 订单分类与实际履约状态一致

截图反馈：顶部“已支付”分类中卡片显示“待发货”，且页签与状态下拉重复。

- 订单与发货页面仅保留顶部状态切换：全部订单、待支付、待发货、运输中、寄存中、已完成、已退款、已关闭。
- 待发货包括待审核配送与待出库。多阶段订单以当前卡片主状态分组：运输中优先，其次待发货，再次寄存中；已完成/关闭/全退遵循原订单终态。
- 服务端在计数及分页前按实际包裹、有效配送申请和寄存余额筛选，使用现有履约信息口径；不在前端筛当前页。
- 财务积分支付记录保留支付查询口径；原接口status参数保持原语义，订单页面改用fulfillment参数。
- 删除重复状态下拉，保留商品/订单搜索与查询、重置按钮。
- 验证页签查询契约、待审核/发货/运输/签收余货寄存/取消后的流转，以及超过一页的分类总数和结果。

本规则替代 admin-mall-layout 中“后台订单页签沿用原订单状态”的界面方案；付款与结算等持久化状态不变。
