# 23: 公司转款产品包核款后激活

**What to build:** 申请人付款前确认资格与协议，财务核实产品包款后自动激活并建立实物交付。

**Blocked by:** 21：邀请确认、分享码与归属调整；22：资格撤销与主理人团队交接

**Status:** ready-for-human

## 验收条件

- [x] 店主包2980元、主理人包19800元，真实SKU分摊之和等于实付货款，标称价值不作资金基数。
- [x] 资格、协议、地址和归属付款前确认，核款后不再单独运营审批。
- [x] 一次实际收款仅建立一次订单和资格，不发积分，产品包与积分充值区分用途。
- [x] 实际公司退款按原收款办理，失败及未决不提前撤资格，成功后联动资格及奖励。
- [x] 未确认8000元、5%、活动及退费政策关闭，缺少此类配置不阻止正常入驻。

## 共同约束

- 以用户最终确认V2为业务依据，复用既有实现，保留原01～18证据和当前工作区改动。
- 交付包含本任务必要的数据、服务、用户／后台入口和验证；历史快照不重算，不虚构缺失资格或资金依据。
- Java显式使用JDK8；新增业务表使用统一六项审计字段，业务数据仅逻辑删除。
- 财务／异步失败保留追踪号与业务键，需补偿状态可查询；外部未决不得当成功。
- 窄范围前端做相关检查；本地替代测试不等于真实微信、银行或真机验收。
