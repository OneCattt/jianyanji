# 12: 产品包退款与代理身份处理

**What to build:** 品牌方办理产品包全部或部分退货及线下退款，根据实际退款结果处理对应代理身份，并保留历史交易。

**Blocked by:** 07：产品包入驻、转款审核与商品交付；10：普通商品售后与微信原路退款

**Status:** ready-for-human

## 验收条件

- [x] 产品包售后关联原申请、产品明细、实际公司收款及交付记录，支持政策内退货和按商品数量部分退款。
- [x] 后台记录退货验货、实际退货款、运费、收款人、线下转账时间及凭证，退款审批或上传材料不等于实际退款成功。
- [x] 已退及办理中款项共同占用原收款和商品剩余可退额度，重复或并发处理不能超退。
- [x] 整包全部退款完成后撤销该次入驻取得的身份，用户后续按其实际有效身份购买；退款未完成不能冒充全退完成。
- [x] 部分退货由品牌方审核是否仍满足入驻条件，保存结论及原因；不新增自动升级、补差或复杂身份变更流程。
- [x] 历史订单、积分及原审核依据保留；身份变化不会重算既有订单价格或删除奖励依据。
- [x] 退款不直接增加可售库存；保留实际退货货款、原产品包货款及累计退款，为按比例冲回原入驻奖励提供依据。
- [x] 验证部分退款人工身份审核、分次全退后仅撤销对应身份、失败不误撤销以及历史订单积分保留。

## Comments

### 2026-10-19 实施交付

产品包退款关联原收款和交付单；线下实际收款人、时间和凭证齐全后完成。`applyPackageRefundIdentity` 同事务执行：部分退款按审核结论，全退撤销本次身份并保留后来身份和历史。membership 与 lifecycle 测试核验分次退款及撤销；实际银行转账事实仍须业务人员核对。

本地测试不代表真实微信交易或线下转账已完成；详细验证及边界见 `docs/development/phase1-implementation.md`。
