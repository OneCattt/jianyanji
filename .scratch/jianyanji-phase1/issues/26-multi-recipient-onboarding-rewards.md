# 26: 多收益人入驻奖励及结算追回

**What to build:** 工作人员按来源分别登记每位收益人的入驻奖励，各自查询结算及处理退款。

**Blocked by:** 23：公司转款产品包核款后激活

**Status:** ready-for-human

## 验收条件

- [x] C邀请新人买C包：直接C及其B各500元；B直邀C：仅B1000元，禁止重复登记。
- [x] 系统提供原来源与核算依据，人工确认登记，不自动生成付款、不转积分。
- [x] 收货、售后期、无未决售后和原资格激活满足后才能结算。
- [x] 累计退半货款时两笔500分别冲回250；分次取整不超原值，全退补齐。
- [x] 已付奖励只形成原收益人欠款，同人后续奖励抵扣或人工实际追回，不跨人扣款。

## 共同约束

- 以用户最终确认V2为业务依据，复用既有实现，保留原01～18证据和当前工作区改动。
- 交付包含本任务必要的数据、服务、用户／后台入口和验证；历史快照不重算，不虚构缺失资格或资金依据。
- Java显式使用JDK8；新增业务表使用统一六项审计字段，业务数据仅逻辑删除。
- 财务／异步失败保留追踪号与业务键，需补偿状态可查询；外部未决不得当成功。
- 窄范围前端做相关检查；本地替代测试不等于真实微信、银行或真机验收。
