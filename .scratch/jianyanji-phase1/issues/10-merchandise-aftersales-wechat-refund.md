# 10: 普通商品售后与微信原路退款

**What to build:** 客服在后台受理普通商品售后，按实际商品和数量退货退款，微信订单原路退款，购买者查询处理结果。

**Blocked by:** 06：后台发货与用户确认收货

**Status:** ready-for-human

## 验收条件

- [x] 后台可配置首期售后期限及政策，客服按原订单受理原因、商品、数量、拟退货款与运费及退货情况，用户通过客服办理并查询状态。
- [x] 支持未发货退款、符合政策的已发货退货及只退部分商品或数量；保留未退商品的正常履约和后续售后关系。
- [x] 已退款与处理中售后共同占用剩余可退数量和金额，并发受理不能超量或超额；待退款数量不得误发。
- [x] 登记退回商品实际收货及验货依据；是否回到可售库存由实际验货决定，退款成功不直接增加可售库存。
- [x] 微信订单退到原微信支付，后台核对原支付、金额及渠道结果；处理中、失败、成功分别可查，提交请求不代表成功。
- [x] 失败可查询渠道结果并安全重试或人工补偿；重复退款通知、重试或并发操作不重复退款或重复释放额度。
- [x] 实际退款记录保留分商品数量、货款、运费、完成时间和原订单关联，为后续原收益冲回提供依据。
- [x] 用户仅能查看本人售后；后台审核、退款和验货保留操作者及原因，需要补偿的失败可按请求和业务编号追查。
- [ ] 验证一单退部分数量后剩余商品仍可交付、并发超退被拒绝、退款未知后查实成功和重复通知；真实原路退款须在商户环境完成集成验证。

## Comments

### 2026-10-19 实施交付

`server/aftersales.ts`、`AfterSalesOperations.vue` 与原生 refunds 已接入。接口测试覆盖部分数量、并发占用、驳回释放、验货独立入库、原单金额、渠道未知后只查原退款及重复成功；微信真实原路退款仍需商户环境人工验收。

本地测试不代表真实微信交易或线下转账已完成；详细验证及边界见 `docs/development/phase1-implementation.md`。

月结后来源退款：普通超期售后继续拒绝；品牌方可由同时具备订单与财务权限的工作人员登记特批原因，保留原政策与审批依据后受理，仍受原单额度和验货约束。连续测试使用真实超期日期验证奖励冲回，避免只在截止同一毫秒串联。
