# 10: 普通商品售后与微信原路退款

**What to build:** 客服在后台受理普通商品售后，按实际商品和数量退货退款，微信订单原路退款，购买者查询处理结果。

**Blocked by:** 06：后台发货与用户确认收货

**Status:** ready-for-agent

## 验收条件

- [ ] 后台可配置首期售后期限及政策，客服按原订单受理原因、商品、数量、拟退货款与运费及退货情况，用户通过客服办理并查询状态。
- [ ] 支持未发货退款、符合政策的已发货退货及只退部分商品或数量；保留未退商品的正常履约和后续售后关系。
- [ ] 已退款与处理中售后共同占用剩余可退数量和金额，并发受理不能超量或超额；待退款数量不得误发。
- [ ] 登记退回商品实际收货及验货依据；是否回到可售库存由实际验货决定，退款成功不直接增加可售库存。
- [ ] 微信订单退到原微信支付，后台核对原支付、金额及渠道结果；处理中、失败、成功分别可查，提交请求不代表成功。
- [ ] 失败可查询渠道结果并安全重试或人工补偿；重复退款通知、重试或并发操作不重复退款或重复释放额度。
- [ ] 实际退款记录保留分商品数量、货款、运费、完成时间和原订单关联，为后续原收益冲回提供依据。
- [ ] 用户仅能查看本人售后；后台审核、退款和验货保留操作者及原因，需要补偿的失败可按请求和业务编号追查。
- [ ] 验证一单退部分数量后剩余商品仍可交付、并发超退被拒绝、退款未知后查实成功和重复通知；真实原路退款须在商户环境完成集成验证。
