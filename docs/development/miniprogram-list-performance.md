# 小程序页面切换与列表加载

## 行为

- 商品、订单、售后、积分余额退款、地址、购物袋、积分明细、奖励、团队分区及资格来源，首屏最多二十条；滚动到底后才追加下一页。
- 奖励详情的冲回、月结、欠款、抵扣和实收历史也分别按二十条读取，触底只继续请求尚有下一页的分区。
- 新分页接口在 `/api/mini/` 下，默认 `page=1&limit=20`，返回 `items`、`hasMore`、`nextPage`。数据库多读取一条判断末页，不执行总数查询。原接口继续服务既有调用方。
- 种草保留编号游标，默认二十条，末页 `nextBefore=null`。首页精选只读取一条、首页种草推荐三条、入驻页面只读取最近一笔申请，均为固定展示区。
- 订单状态、积分类型、奖励类型及售后订单编号在数据库筛选后分页；金额汇总覆盖完整业务记录。
- 正常往返复用一分钟内的已加载内容；业务写入成功、登录账号变化或下拉刷新后重新读取。刷新时保留原列表，失败不推进下一页；重复触底不重复发请求，旧筛选响应不会覆盖新筛选。
- 追加列表只传新增行到视图层。商品规格按当前页批量读取，商品列表不携带长说明和详情图片；列表图片按需加载，底栏去掉背景模糊。
- “我的”只在确认身份期间限制依赖身份的入口；设置、品牌介绍及课程可直接打开。邀请和钱包汇总并行读取，钱包明细按需分页。
- 本人订单列表仅清理本人的过期待付款订单，没有过期项时不进入全局写事务；后台定时清理及支付未决状态保护规则继续生效。
- 购物袋金额统计和结算覆盖全部已选商品，包含尚未滚动加载的条目；结算时服务端重新校验价格与库存。选择地址按本人地址编号直接读取，不受地址第一页范围影响。

## 验证

- 小程序真实页面与共用模块行为回归 53 项通过，覆盖加载二十条后追加、末页、重复触底、失败重试、筛选竞态、缓存失效、入口点击、地址、积分付款和奖励详情历史分区。
- JDK 8 执行相关后端测试 31 项通过，无跳过，包含独立 MySQL 库中的真实查询：41 条商品按 20/20/1 返回、完整购物袋汇总与结算、混合奖励与冲回分页、奖励详情历史分页与结算筛选、用户隔离，以及仅释放本人明确未支付的过期订单。
- `node scripts/check-miniprogram.cjs` 验证 22 个注册页面的原生 WXML/WXSS、JavaScript、JSON 和页面完整性。
- 未采集真机帧率，实际手势和转场流畅度仍需在体验版验证。

## 生效顺序

先部署包含 `/api/mini/` 接口的后端，再重新编译、上传小程序。本次无需数据库结构迁移；现有已发布小程序仍调用原接口。
