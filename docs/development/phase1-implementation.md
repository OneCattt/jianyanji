## 资金与履约约束

- 金额和积分统一使用整数百分之一；人民币分、积分百分之一与展示值区分，1 元公司订货款发 1 积分。产品包货款只交付商品，不额外发等额消费积分。
- 下单保存原身份、归属主理人、商品规格、C 成交单价和当时 B 价、运费、地址、售后期限与政策。后改配置不重写原依据。
- 微信支付使用原 appid/mchid、金额、商户单号和流水核验；网络失败为结果未明，查询原交易。付款页返回或提交请求本身均不代表到账。
- 待付款订单只占库存。微信确认到账或积分实际扣款时才扣可售库存，发货不再次扣库存。可发量扣除未发货退款及售后占用，已出库退货不重复扣可发量。
- 钱包逐收款批次分摊消费，退款返回原批次。未用积分退现金先占积分和原收款额度，实际退款成功才扣积分；unknown 保留占用。
- 普通售后遵循原期限。超过期限的特殊退款须工作人员同时具备订单和财务权限，填写品牌方特批原因，原政策、特批原因及操作人均留痕；因此可实际办理月结后来源退款及奖励冲回。特批不放宽原数量、原款、验货和原渠道限制。
- 商品退款成功、积分返还、产品包身份处理和奖励冲回在同一数据库事务内执行。失败回滚，不提前改变用户余额或身份。
- 产品包全部货款分次退完后撤销本次入驻身份，不覆盖后来取得的其他有效身份；部分退款记录人工身份审核结论。
- 入驻奖励按目标身份两档固定金额，店主订货收益按原 C 成交价减原 B 价乘数量，不含运费。支付方式不改变收益。首期由人员登记和核算，不自动生成或打款。
- 月结要求原商品收货、原售后期结束且没有未处理售后。公司线下转账须登记实际收款人、时间、金额和凭证；已付来源退款形成待收回额，后续奖励先抵扣，不足人工追回。

## 权限与排查

后台分别使用 `content:manage`、`catalog:manage`、`orders:manage`、`onboarding:manage`、`finance:manage`、`rewards:manage`，继承账号、用户与审计权限。前端按权限显示入口；接口独立验证。用户业务接口按会话身份读取本人数据，不能通过前端编号越权访问。

订单、付款尝试、原公司收款、钱包批次/流水、售后、现金退款、奖励与结算均保留业务编号。关键写操作记录操作者、原因、requestId 与结果；微信网络异常保留原尝试及未知状态供查询，不在日志打印密钥。服务端每 30 秒分批核查支付并清理可关闭的超时订单，单进程防重入、数据库租约控制重复渠道操作；停机等待当前核对结束后关闭数据库。

业务数据使用逻辑删除及审计字段。当前数据库为 Node 内置 SQLite；没有声称已经迁移 MySQL。多实例或 MySQL 部署须先落实共享数据库迁移、事务及租约行为的同等验证。
