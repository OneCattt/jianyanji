# V2.1 首期线下交易

依据：2026-10-20 用户确认“首期不做支付相关，支付均线下交易”。规格见 [V2.1](../requirements/清欣简妍肌首期需求规格说明V2.md)，实施跟踪见 [任务 36](../../.scratch/jianyanji-phase1/issues/36-offline-transactions.md)。

## 业务办理

| 业务 | 实际收付款与系统操作 |
| --- | --- |
| 普通商品 | 用户下单并按订单号线下付款；财务在“普通订单收款”选原单，核实实际到账、原流水和凭证后登记，转为待发货。普通货款不发积分 |
| 产品包 | 按既有邀请、资格及协议确认申请，线下付款后从产品包申请核款；核实到账后激活对应资格，建立商品交付，不额外发积分 |
| 积分充值 | 代理线下向公司转款，财务从“积分充值收款”核实后按 1 元对应 1 积分发放；与普通货款和产品包分开 |
| 积分订货 | 保留原批次余额扣减、原身份价格和库存结算；积分不足提示线下充值或整笔线下付款 |
| 订单退款 | 运营审核及必要退货验收后，财务线下退款并登记实际收款人、付款时间和凭证；成功登记后联动原资格及奖励。积分订单退回原消费批次 |
| 未用积分退现金、奖励 | 沿用原收款限额与积分占用、人工登记、线下实际付款及结果核实规则 |

待核款不能发货；提交订单或上传截图不能代替财务核实。核款前关闭或过期的订单不可直接登记为成功，须联系品牌方核对款项及原订单，避免重复转款。待核款有效期仍使用配送政策的 `pendingMinutes`（5～1440 分钟）。上线前应按财务核款频次设置该值，用户付款和财务核款都须在有效期内；仅付款时间早于截止但核款已超期，也不能恢复原单。过期任务可能已释放库存，已到账例外须由财务人工核对并处理退款或重新下单，不能绕过状态校验强行发货。

## 接口与权限

- 新增 `POST /api/admin/orders/{id}/receipt`，只允许 `finance:manage`。请求字段：`sourceChannel`（线下公司收款渠道 `bank`／`wechat_company`）、`accountRef`、`externalTransactionId`、`amountCents`（必须等于原单应收总额，整数分）、`receivedAt`（过去 ISO UTC）、`evidence`、`reason`、`verified=true`。用户和用途由服务端从原订单获取。
- 响应为 `{order, receipt, alreadyPaid}`；相同原流水重复核款幂等，换流水不能覆盖已有收款。同一公司流水不可跨订单、产品包或积分充值使用。
- `GET /api/admin/orders`、`GET /api/admin/orders/{id}/payment`、`GET /api/admin/orders/{id}/fulfillment`、`GET /api/admin/refunds` 允许订单或财务权限读取；发货、审核及退款写入仍分别校验原权限。
- 原 `POST /api/admin/refunds/{id}/offline` 扩展为普通线下订单和产品包线下退款，仍要求财务权限、真实确认和凭证；积分订单不能通过此入口退现金。
- 原线上支付发起、通知、查单、关单、渠道退款及退款查询返回 `409 ONLINE_PAYMENT_DISABLED`，不调用外部支付渠道。只读原订单及收款明细保留。
- 支付渠道定时核查停用，订单过期释放任务保留。已有微信商户环境变量不会重新开启首期线上交易；小程序登录、分享及视频仍正常配置。

## 数据与一致性

新增 Flyway `V11__offline_order_receipts.sql`，沿用 `company_receipts` 审计和逻辑删除字段，扩展 `purpose=order` 和普通订单 `order_id`。活跃订单收款使用条件唯一索引，原公司收款流水唯一约束继续防止资金跨用途复用；已有收款、订单、退款及钱包记录不重写。

普通核款经 `Db.tx` 将原收款登记、库存扣减、订单已付状态及凭据一次提交；财务操作人维护订单、库存及凭据审计字段，到账时间使用实际 `receivedAt`。普通收款不产生积分钱包批次或流水。退款登记、原收款累计退款额、商品数量、资格和奖励冲回同事务完成，任一失败整体回滚，可按原退款单重试。

退款凭证完整保存在 `proof`（最多 1000 字符），线下退款不占用仅存渠道退款编号的 `channel_ref` 字段。

失败日志保留 `requestId`、订单或退款编号、财务经办人员和原因；成功核款及退款操作留审计。失败退款保留原申请和真实业务状态，不提前计为成功。

## 更新与环境

先备份目标数据库，停止旧服务写入，再由新版 Flyway 应用 V11。首期不再要求支付商户、支付 PEM 文件、API V3 密钥或支付通知域名，`.env.example` 已移除这些必填引导。

更新前只读核对是否存在历史线上未决交易：

```sql
SELECT p.id, p.order_id, p.number, p.state, p.last_request_id
FROM payment_attempts p
JOIN orders o ON o.id=p.order_id AND o.is_deleted=0
WHERE p.is_deleted=0 AND p.state NOT IN ('closed','success');

SELECT id, order_id, number, status, request_id
FROM refunds
WHERE is_deleted=0 AND status IN ('processing','unknown');
```

如存在真实历史线上未决资金，先由财务按原单号核实和处理，再切换服务；不能通过重建订单、改为线下已付或清空原状态规避。新版保留这些记录并阻止重复收款，不再自动访问渠道。
