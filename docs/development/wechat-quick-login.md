# 微信快捷登录与核款资料交付记录

2026-11-03，本地实现。用户追加授权部署后端及后台管理页面，小程序只提交源码，不上传、不提审、不发布；实际发布记录在本文末尾追加。

## 使用变化

用户在我的、购物袋、商品、入驻、课程、钱包或个人设置主动登录时，就地显示底部面板。首次同意在面板展示运营主体、用途、政策全文与微信隐私指引入口；需要微信原生同意时仍通过原生按钮完成。不会因浏览或静默读取而弹登录。

主入口为微信手机号快捷登录，保留不绑定手机号的微信登录。拒绝手机号授权不自动登录，用户可改选普通微信登录；资料不完整时提供昵称填写及稍后完善。昵称使用 `type="nickname"`，按表单提交的最终值保存；没有静默读取昵称。登录后原购买可继续，不必再点第二次。个人设置可单独授权更换手机号；昵称表单不携带旧手机。钱包充值说明展示本人昵称与手机号，提醒总部同时核对并提供转账流水，不自动核款或发积分。

## 数据与接口

- 原有 `POST /api/auth/wechat` 接受可选 `phoneCode`；始终以微信服务端返回的原 openid 找到本人，不按手机号建号或合并账号。手机号换取失败时不创建用户、不签发会话。
- 新增 `POST /api/me/wechat-phone`，仅当前登录本人可用。微信凭据、手机号代码在服务端交换，访问令牌仅缓存服务端内存；一次性授权码不自动重试。
- `PATCH /api/me` 按实际提交字段更新，昵称单独提交时保留实时手机号；历史手填电话改变后清除原验证状态。本人响应新增 `phoneVerified`，不允许前端写入该状态。
- V15 为用户补充可空 `phone_verified_at`，新增 `wechat_exchange_logs`，遵守审计字段及逻辑删除约定；不重算历史账号、积分、交易、身份或归属。
- 微信登录、stable_token、getuserphonenumber 均保存脱敏参数及响应结构、错误码、HTTP状态、耗时、request ID与关联键，覆盖成功、业务失败、HTTP异常、非JSON和超时。密钥、令牌、一次性代码、openid及完整手机号不落日志；匿名身份调用用不可逆摘要及request ID关联登录审计，已登录绑定可按user编号检索。

## 发布与回退

先备份并部署包含V15的后端，再上传新版小程序；数据库DDL可能隐式提交，应用回退不等于撤销DDL。V15是新增字段和新表，回退应用时保留这些数据，不使用物理删除或整库回灌清理新日志。若确需恢复数据库，先停写并依据发布前一致备份与后续业务记录制定恢复方案，避免覆盖发布后交易。

旧版小程序不识别验证状态，且可能按旧表单修改手机号；若回退到旧版资料编辑后再恢复新版，须重新核查期间变更手机号的验证来源，不能沿用不再匹配的旧验证标记。

发布前在微信公众平台确认非个人主体的微信认证与手机号能力可用额度，同步发布包含手机号授权、昵称填写和核款用途的隐私保护指引；仅完成ICP小程序备案不能证明这些能力已开通。政策版本已更新，旧本机同意会按既有规则失效并清理旧会话及业务选择，重新登录沿用原用户账号。

待验收：目标环境V15迁移、脱敏日志真实落库及权限、微信真实取手机号、原生隐私指引、昵称建议与内容安全、拒绝授权/额度耗尽、老用户积分订单一致、真机登录后购买/核款路径。后端发布与小程序发布须分别记录实际提交及构建产物哈希。
