# 小程序隐私保护接入与提审核对

更新日期：2026-10-22。适用首期线下收退款、积分订货及代理服务。

## 已实现

- 隐私政策位于小程序「个人设置 → 隐私保护」及「品牌与服务」；地址填写页面也有入口。普通查看不记录同意。
- 四类登录入口（个人设置、商品加购、购买、销售分享）统一先展示政策，主动勾选并点击同意后再调用微信身份登录。拒绝、系统返回、授权失败不会提交登录或个人业务。
- 首页、商城、商品、品牌图文、课程和产品包说明可匿名浏览；未同意时请求不带旧登录令牌，私有 API 和所有业务写入在网络发出前拦截。服务端本人及权限校验继续独立执行。
- 接入微信 `getPrivacySetting`、`openPrivacyContract`、`agreePrivacyAuthorization`、`onNeedPrivacyAuthorization`、`requirePrivacyAuthorize`。本机记录不代替微信侧授权；恢复已登录会话时先共享检查一次微信隐私状态，检查期间不发送带身份请求；出现新待同意指引或状态读取失败时清理旧本机同意与登录，后台读取不强弹授权，用户主动登录时再请求确认。
- 本机 `jyj_privacy_consent` 保存政策版本、主动同意时间和当时的运营主体、隐私联系方式。这是本机交互记录，不声称已建立跨设备服务端同意证据库；清理微信缓存后会重新询问。
- 正常退出保留本机同意，清除令牌、地址选择、结算选品、销售和邀请候选；撤回同意再清除同意记录、重建页面栈。断网不妨碍撤回，已发出的请求可能已在服务端完成，不以撤回取消交易。
- 会话变化或撤回后，原会话的在途响应不会写回个人数据，也不会删除后来登录的账号令牌。注销与删除采用品牌方人工核验办理，不自动销毁历史交易。

## 品牌后台必须配置

在「品牌与经营说明 → 品牌资料编辑 → 隐私保护」维护以下两项，保存时填写修改原因：

| 字段 | 内容要求 |
| --- | --- |
| 运营主体全称 `privacyOperator` | 实际负责处理用户个人信息的主体全称；核对小程序主体。不能将公司收款户名未经核实直接当作运营主体。 |
| 隐私联络方式 `privacyContact` | 可实际受理隐私咨询、查阅、复制、更正、删除及账号注销的邮箱、电话或其他联系方式；指定负责人。 |

两项须同时填写或同时清空。未配置时，政策正文仍可阅读，匿名浏览可用，但不能完成首次同意及登录。旧版管理请求省略两项时在事务内保留现值。沿用已有 `settings` JSON，不增加数据库表或迁移。

后台与后端需一起部署后再上传新版小程序，否则旧后端不接受新隐私字段。当前代码不包含真实公司全称或虚构客服电话；部署不能代替资料确认。

## 微信公众平台配置

进入对应 AppID 的「用户隐私保护指引」配置入口（以公众平台实际菜单为准），按真实业务填写并发布。不能只上传代码而不配置平台指引。

| 实际处理的信息 | 用途及必要性 |
| --- | --- |
| 微信用户标识 openid | 用户主动登录后识别本人、建立账号及校验权限；登录临时 code 仅换取身份。 |
| 昵称、联系电话 | 用户手填昵称、选填联系电话，用于账号展示和业务联系；不自动获取微信头像、昵称或手机号。 |
| 收货人姓名、电话、地区及详细地址 | 用户提交收货地址，用于订单配送与售后；不是读取微信地址簿或精确定位。 |
| 购物袋、订单、物流及售后 | 完成订货、履约、售后处理，保存成交与地址快照。 |
| 公司核款、积分及奖励账目 | 由授权人员登记真实线下收退款，核算积分来源、消费退款及奖励结算；无首期微信在线支付。 |
| 邀请、归属、代理资格、分享码与团队信息 | 核验入驻及单笔销售归属，展示已授权范围内的关系与收益；持分享码者可查询必要代理昵称、编号与身份。 |
| 网络及安全运行信息 | 网络连接、限流、防刷、故障排查与审计。媒体服务会接收必要连接信息。 |
| 本地存储与剪贴板写入 | 保存登录、同意及业务选择；用户主动点击时复制订单号、运单号、分享码或联系方式。不读取剪贴板。 |

按平台现有选项如实映射；不存在对应预设时按实际支持的说明字段补充。不要声明当前未使用的获取手机号、头像昵称、相册、相机、麦克风、通讯录、精确定位能力来凑清单，也不要以未调用敏感 API 为由漏报手动填写的地址、电话和交易资料。

接收方及受托方需核对：腾讯微信、实际阿里云基础设施、实际媒体域名及服务商、品牌仓与承运物流。当前源码支持配置 HTTPS 媒体地址，提审前按已发布内容核对实际域名，不能由代码中未包含广告 SDK 推断所有外部内容均已审计。

在微信后台同步真实运营主体、隐私负责人联系方式、用途、保存期限及权利办理方式，并确认平台指引与程序政策一致。政策正文的来源是 `miniprogram/utils/privacy-policy.js`，不是旧微信支付规格。

## 权利申请办理

1. 用户通过「个人设置 → 个人信息与账号注销申请」查看办理说明，复制隐私联系方式后自行联系；复制不会自动提交申请。
2. 隐私负责人登记申请类型、时间、必要业务编号及联系方式，仅核验处理所需身份信息，不要求密码或无关身份证明。
3. 核对本人资料与未完成订单、售后、未用积分、待结奖励和代理关系；处理更正、可依法删除的资料及注销申请。删除采用逻辑删除并限制用途，不删除或重写依法需保留的成交、财务与资格来源。
4. 通常十五个工作日内回复办理结果、不能立即办理的理由及后续途径；可依法删除的资料和备份按相应周期落实，未完成交易通过正常业务流程处理。
5. 客服不能把“退出登录”“本机撤回同意”“注销账号”“删除历史数据”混为一项。撤回仅处理本机同意与后续请求，平台授权状态需通过微信提供的管理入口处理；其他设备和服务端法定义务不因此自动终止。

政策中的境内存储、备份、交易信息不少于三年、依法需要的安全日志不少于六个月及响应时限，均需品牌方在实际运营、数据库和日志保留配置中落实；本次代码未新增数据定期物理删除或自动注销功能。

## 安全日志保留配置

`deploy/logrotate-jianyanji` 已改为 `rotate -1`、`maxage 200`，继续每日轮转及 `maxsize 20M`。按时间保存 200 天，避免高流量一天多次轮转时因“只保留 7 份”提前清除安全日志。该配置依赖支持 `rotate -1` 与 `maxage` 的目标 logrotate 版本；发布时先检查版本与 dry-run，再安装：

```bash
sudo logrotate --debug deploy/logrotate-jianyanji
sudo install -m 0644 deploy/logrotate-jianyanji /etc/logrotate.d/jianyanji
```

随后核对系统 logrotate 定时任务、历史日志归档、访问权限和磁盘容量告警。配置只影响未来轮转，不能恢复已被旧配置清理的日志；归档不应因应用版本回退恢复为 7 份。当前仅修改仓库模板，尚未安装到服务器；若目标版本不支持上述时间保留方式，先升级或配置等效归档，不能以现有 7 份记录宣称满足六个月要求。

## 政策更新

实际收集范围、用途、接收方等发生实质变化时，同步更新政策正文与微信后台指引，更新 `utils/privacy.js` 的 `POLICY_VERSION` 并随小程序发布。新版本启动不复用旧同意，会清理旧登录及业务选择，要求用户再次确认。只修改公开运营资料不自动升级小程序政策版本，运营主体发生变化须按实质变化处理。

## 本地验证及外部边界

验证结果见 `.scratch/miniprogram-privacy/issues/01-privacy-policy-and-consent.md`。

微信开发者工具及单元模拟不能替代以下实际验收：

- 运营主体和隐私负责人真实有效，按政策受理申请；实际地域、备份、日志及财务记录保留策略符合公示。
- 微信公众平台指引已发布；用真实 AppID 与设备分别验证首次同意、拒绝、重新授权、打开平台指引、版本升级及撤回。
- 真机检查商品浏览、商品加购、登录、地址保存、下单、线下核款与售后路径，以及视频和图片实际域名。

本次未上传、提审或发布小程序，未部署服务器，也未修改现有数据库资料。
