# 01 登录、身份识别与后台权限实施记录

实施日期：2026-10-19。功能已实现并通过本地验证，任务标记为 `ready-for-human`，待使用实际微信 AppID 在开发工具及真机完成最后验收。

## 已交付

- 微信原生小程序：首页匿名入口、商城准备中状态、我的、微信登录、身份展示、昵称和联系电话维护、退出登录。
- 浏览器购买端：与小程序复用真实服务端接口，本地显式开启调试后可体验游客与已存在的两类代理身份。
- 品牌方后台：账号登录、当前功能入口、用户资料脱敏查询、工作人员新增/授权/启停/逻辑移除、按业务对象查操作记录。
- 持久化与权限：用户身份独立于后台权限，资料接口不允许修改代理资格；令牌仅保存摘要；权限每次请求核对，账号停用撤销旧会话；逻辑删除可重新创建同名账号并保留旧记录。
- 防止误操作：至少保留一个启用的账号管理员；后台写入校验同源；登录有限流，密码随机盐 scrypt 摘要保存。

启动、演示账号、微信导入和首次正式管理员初始化见[项目说明](../../README.md)。接口约定见[身份接口说明](identity-api.md)。

## 联调修复

浏览器发现前端模块名与 `/api` 前缀代理冲突，已重命名模块并把代理匹配限定为 `/api/`。同时显式保留代理请求原始 Host，使后台同源保护在开发代理下也能正常工作。完整浏览器操作在修复后通过。

弹窗使用原生 dialog 管理焦点、Esc 关闭和背景隔离；手机浏览器保存结果显示在底部导航上方。样式提供可见焦点和减少动效支持。

## 微信环境待验收步骤

1. 使用实际 AppID 导入小程序，服务端填写匹配的微信参数，关闭两端本地调试登录，配置 HTTPS request 合法域名。
2. 以新微信用户登录，确认身份为游客；编辑本人昵称及联系电话后重新进入仍可查询。
3. 使用已有真实 B/C 业务数据登录，确认身份保留；不通过修改资料或登录参数开通代理身份。
4. 在真机检查微信导航区域、底部安全区、登录和保存按钮，以及软键盘打开后的资料编辑。
