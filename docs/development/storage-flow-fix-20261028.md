# 寄存流程修复交付记录（2026-10-28）

依据用户在流程梳理后的“修复”指令实施。修复前诊断保留在[流程梳理](storage-flow-review-20261028.md)，业务规则仍依据 ADR 0007。

## 修复结果

| 问题 | 修复后的行为 |
| --- | --- |
| 全寄存显示待发货、首批签收后仍显示运输中 | 服务端复用订单明细、提货单和实际包裹生成履约展示状态；没有在途包裹且只剩留仓货品时显示寄存中，部分签收后显示余货寄存；保留原支付与结算状态 |
| 订单筛选及角标与实际配送不符 | 待发货、运输中按实际待配送数量/有效提货申请/未签收包裹在数据库分页前筛选；新增含寄存筛选；角标使用相同筛选条件 |
| 普通新购首发在提货模块，订单入口难办理 | 后台订单列出有效配送单，可直接打开对应配送详情并审核、驳回、发货或取消；被配送单占用的数量不再显示可从旧入口直接发货 |
| 取消混合配送后不清楚新购商品去向 | 确认与结果页说明：释放原寄存占用、退本次运费；新购商品继续按原购买订单处理，不自动转寄存。取消后未分配到有效配送单的新货可从原订单普通发货入口继续配送；不改变已付款购买关系 |
| 返回购买页面丢失选择 | 套餐、权益包重新加载时保留仍对应同一商品及数量的发货选择；手动调整数量时同步配送模式；套餐确认按实际发货/寄存件数提示 |
| 合并寄存不能继续编辑、不能全部清空 | 再次进入回填原选择，支持清空全部选择后返回；保留跨页选择和换号清理 |
| 报价失败或迟到造成误提交 | 修改数量即失效原报价，更新期间禁止提交；只接受最新请求结果，失败提供重新报价入口；保留商品展示供继续调整 |
| 寄存卡片数量混用原订单口径 | 小程序和后台统一展示寄存总量、寄存累计已提、剩余寄存、占用和可提；首次配送不再计入“寄存已提” |
| 独立提货确认缺少地址信息 | 增加选址入口，确认弹窗显示收件人、电话、完整地址、件数及费用 |

纯新购及合并提货仍复用现有提货单、发货记录和事务机制。本次不自动把新购配送转成寄存，不改变三档运费、商品货款退款、身份及奖励规则；一张提货单仍整单发货、整包签收。
