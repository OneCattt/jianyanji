## 1. 项目目标

首期完成代理管理、双支付订货、品牌方发货、必要售后和人工奖励核算结算的业务闭环，使公司收款、积分、订单支付、退款及奖励能够逐笔查询、互相对应。

三个核心验收场景：

1. 游客登录后可以通过微信支付购买商品，并查询发货信息。
2. 代理可以直接微信付款，也可以向公司转款、获得积分后订货；同一身份不因支付方式不同而改变商品价格。
3. 品牌方可以审核代理、确认收款并发积分、处理订单和退款、登记奖励与实际结算，关键操作均留记录。

## 2. 角色与业务术语

| 角色或术语 | 定义 |
| --- | --- |
| 品牌方 A | 负责经营、收款、代理审核、供货和售后的公司；后台工作人员按授权操作 |
| 主理人 B | 享有主理人身份权益和价格的代理 |
| 店主 C | 享有店主身份权益和价格的代理 |
| 游客 D | 尚未取得代理身份的购买者，包括已登录的非代理用户；登录不等于成为代理 |
| 公司转款 | 代理向品牌公司支付的款项，由指定工作人员核实到账 |
| 订货积分 | 公司收款后按比例发给代理、用于订货的余额，以下简称“积分” |
| 微信付款 | 小程序商品订单通过微信支付付款 |
| 入驻产品包 | 入驻所需购买并交付的一组商品，货款不额外形成等额可消费积分 |
| 积分余额退款 | 将未使用积分对应的公司转款退回，并扣回对应积分 |
| 订单退款 | 对商品订单退钱或退积分；与积分余额退款分别处理 |
| 部分退款 | 对部分商品或数量退款，保留其余商品的履约与售后关系 |
| 直接邀请人 | 直接邀请申请人加入代理的人 |
| 归属主理人 | 经品牌方确认的业务归属主理人，不等同于直接邀请人 |
| 代理奖励 | 根据入驻或订货等业务约定支付的报酬，与订货积分分开记录 |
| 入驻奖励 | 直接邀请他人完成入驻对应、归属于直接邀请人的奖励 |
| 店主订货收益 | 店主订货对应、归属于该店主归属主理人的收益 |
| 订货价差 | 来源店主订单中商品实际成交单价与当时主理人订货单价的差额，不含运费 |
| 可结算奖励 | 商品收货完成、售后期结束且无待处理售后，符合结算条件的奖励 |
| 奖励抵扣 | 将同一人待归还的已付奖励从其后续应结算奖励中扣除 |

权限原则：购买者仅查看自己的地址、订单、积分和售后记录；后台工作人员仅操作被授权的功能。品牌方使用购买端时，同样遵循实际购买身份的规则，后台权限不自动形成商品优惠。

## 5. 主要业务流程

### 5.1 代理申请与开通

查看身份权益 → 登录并填写申请 → 品牌方核查条件及邀请归属 → 审核通过或驳回 → 展示结果。

审核通过后才享有代理价格和积分订货能力。申请中、被驳回的用户仍可按当前有效身份购买。入驻产品包货款用于交付对应商品，不另发等额可消费积分；另有公司转款用于积分订货时，按独立收款记录发积分。

产品包通过向公司转款购买，品牌方核实到账后登记产品包收款、安排交付并审核身份；必须关联申请、实际收款和商品交付。同一收款不得同时登记为产品包货款和积分发放来源。

整包全部退款完成后，取消该次入驻取得的身份，后续新订单按实际有效身份计价；历史订单、积分和奖励记录保留，不自动抹除或重算。部分退货由品牌方审核是否仍满足该身份条件并记录结果。

### 5.2 微信支付购买

选商品 → 购物袋或立即购买 → 确认订单与配送费用 → 提交订单 → 微信支付 → 核实支付结果 → 待发货 → 发货 → 收货完成。

小程序展示“支付成功”必须有实际支付成功依据。关闭支付窗口、页面返回或请求超时不能直接认定为成功，也不能直接认定未扣款；结果未明时展示“付款结果确认中”，允许查询原订单。

### 5.3 公司收款后积分订货

代理按说明向公司转款 → 指定人员核实到账 → 登记收款及归属代理 → 发放等额积分 → 代理选购 → 确认积分付款 → 扣减积分并记录支付 → 待发货。

展示余额不足时，可引导查看公司转款说明，也可选择微信支付整笔订单；不得在积分扣款状态不明时再次发起微信付款。

### 5.4 商品订单售后

用户联系客服 → 工作人员登记订单、商品、数量、原因及拟退款金额 → 审核 → 如需退货则登记寄回及收货结果 → 执行原路退款 → 确认退款结果 → 更新售后记录。

首期支持未发货退款、符合售后政策的已发货退货，以及按商品数量部分退款。已发货商品需要退回时，登记并核实实际收货、验货结果后处理退款；具体可退条件由售后政策明确。

退款失败或结果未明时保留处理记录，允许继续查询和人工补偿；不得仅凭点击退款按钮就显示退款完成。部分退款不能影响未退商品的正常履约，涉及原奖励的按实际退款范围记录人工冲回。

### 5.5 未使用积分对应款项退款

代理联系客服 → 品牌方核验资金来源和可退积分 → 人工审核 → 按规定退回公司转款 → 确认退款结果并处理积分 → 留存凭证。

必须防止退款办理期间，同一部分积分又被消费。审核占用、退款成功扣回、失败或驳回释放须构成闭环；具体实现不要求采用某种技术方案。

可受理的余额包含普通积分订单退款退回、且尚未再次消费的积分。任何余额退款均需对应原公司收款，在扣除原款已退金额后核定上限；同一笔资金不因先退积分、再申请现金而重复退款。

### 5.6 人工奖励核算与结算

根据已确定的奖励业务核对来源 → 人工计算并登记奖励对象、金额、依据 → 登记实际付款及凭证 → 更新结算情况 → 来源退款时人工核算冲回、跟进已付差额。

首期仅做两类奖励：直接邀请人获得入驻奖励，归属主理人获得店主订货收益；不做多层奖励。品牌方人工核对来源及对象，计算金额，通过公司线下转账结算并登记收款人和凭证。代理通过“我的奖励”查询本人记录，不提供在线提现。

来源业务退款时核算冲回金额。尚未支付部分减少待结算额；已经支付部分优先抵扣同一人后续应结算奖励，仍不足则人工追回并持续记录。仅登记了待追回金额不能视为已收回，抵扣和实际付款也不能重复计算。

入驻奖励按新加入者为店主或主理人设置两档固定金额；店主订货收益按各商品的原成交价与当时主理人价之差乘数量核算，不含运费，两种支付方式同规则。商品收货完成、售后期结束且无待处理售后后可结算，每月集中转账一次。

部分退款时，订货收益冲回退货商品对应的原收益，入驻奖励按产品包退款货款比例冲回；全部退款冲回全部。具体金额和核算示例见第 6.1 节；两档奖励金额、售后期和月结日期由品牌方上线前填写。

## 6. 功能需求与验收标准

### FR-01 登录、身份与信息保护

- 未登录可浏览商品与品牌信息，涉及下单和个人记录时要求登录。
- 新用户登录后仍为 D 身份，只有审批通过才能成为 B 或 C；已开通代理登录时保留其当前有效身份。
- 购买者不能访问其他人的订单、地址、积分或售后记录。
- 后台不得由购买者身份自动获得访问权限。

验收：普通用户登录后看到零售价；审核开通店主后按店主价购买，且不能通过修改请求读取他人订单。

### FR-02 商品、规格与价格

- 价格与库存落实到可购买的具体规格；商品只有一个规格时也可直接购买。
- 每个规格明确维护零售价、店主价、主理人价，首期不叠加多种折扣算法。
- 采用价差收益的规格须校验主理人价不高于店主价，避免负价差；收益只按真实成交价格核算。
- 页面使用“元”和“积分”区分支付单位。同一身份购买同一规格，328 元对应 328 积分；该数值仅为说明示例。
- 价格、商品、规格及购买数量以结算时核验结果为准；结算信息变动应提示用户再次确认。
- 已成立订单保存成交商品、价格、身份、运费等信息；后续改价不重算历史订单。
- 店主订单同时保存当时主理人订货单价及归属依据，供后续人工核算价差；不能结算时再查询最新价格替代。
- 下架、库存不足、未配置该身份有效价格的规格，不得生成可支付订单。

验收：同一店主用两种支付方式购买同一件商品，商品价相同；改价后已有订单详情保持原成交价。

### FR-03 购物袋与收货地址

- 支持勾选、调整数量、移除购物袋条目，清楚展示商品种类数与总件数。
- 收货信息包含收货人、联系电话、地区、详细地址，支持默认地址。
- 下单时保存收货信息快照，之后修改或移除地址不改变已有订单。
- 不配送地区不能提交订单；运费按固定规则在付款前展示。

验收：商品 A 两件、商品 B 一件显示“2 种、3 件”，合计按数量计算。

### FR-04 代理入驻与归属

- 展示可申请身份的权益和条件，记录申请身份、联系人、联系电话及申请时间。
- 审核记录包含审核人、时间、结果、驳回原因，以及最终确认的邀请人和归属主理人。
- 相同用户不能因重复提交或重复审核形成重复有效代理档案。
- 首期不提供购买者自行变更邀请或归属关系的入口。
- 无邀请人或由店主邀请时，由品牌方在审核时指定归属主理人，不能仅凭邀请人身份自动推算；记录邀请人与归属主理人各自的确认结果。
- 审核只开通已核实满足条件的身份，不自动赠送积分或发放奖励。
- 入驻产品包全部退款完成后记录身份撤销，仅取消该次申请取得的身份；部分退款由品牌方审核身份条件并记录。身份变化不追溯改写历史订单、积分或奖励。

验收：驳回后用户能看到原因；审核通过后身份和价格生效，审核依据可查询。

### FR-05 公司收款与积分发放

- 代理能查看有效公司收款信息、转款备注要求和客服联系方式。
- 工作人员登记代理、实际到账金额、到账时间、收款账户标识、原始收款流水及必要凭证。
- 按 1 元对应 1 积分发放；金额与积分支持两位小数，使用精确数值计算。
- 一笔原始收款首期对应一名代理，并明确收款用途；产品包货款不能再次作为积分发放来源，相同积分用途收款不得重复发积分。
- 发放完成时同步产生积分流水；重复操作不能重复增加余额。
- 已发放记录不可直接覆盖；录错时必须走有来源、有原因、有操作人的纠正记录，不能无痕改余额。

验收：公司收款 1,000 元，代理获得 1,000.00 积分；重复确认同一笔收款，积分仍只增加一次。

### FR-06 订单与支付

- 支持立即购买和购物袋结算；一笔订单只使用微信或积分其中一种支付方式。
- 游客登录后可用微信付款；B、C 可以选择微信或积分付款。
- 积分支付前清楚展示实扣积分、可用余额，并由购买者最终确认。
- 创建待付款订单不等于完成积分扣款；在用户确认积分付款时完成扣减及支付登记。
- 同一订单只允许一次有效支付；两端同时支付、重复点击、重复通知均不能重复收款或扣积分。
- 支付方式切换前应确认原支付未成功且无未解决的支付结果。
- 支付结果未明时进入查询或处理流程，不重复创建替代订单规避原状态。
- 支持继续支付和取消尚未支付的订单；支付与取消冲突时不得同时判为已关闭且已支付。
- 创建订单、库存占用、支付、取消及退款之间必须一致，不能超卖、超扣或遗留永久占用。

验收：重复点击积分支付只扣一次；微信支付通知重复到达只记录一笔有效支付；支付后不能按未付款订单直接取消。

### FR-07 订单查询、发货与收货

- 用户可按待付款、待发货、已发货、已完成等状态查询订单。
- 详情包含商品规格、单价、数量、费用、支付方式、实付、地址、物流及售后结果。
- 品牌方只能对符合发货条件的已支付订单发货；退款处理中应避免继续发出待退款商品。
- 发货登记物流公司、单号、时间及操作人；可纠正错填信息并保留记录。
- 用户可查看、复制运单号并确认收货；首期不依赖自动物流轨迹。
- 退款不自动代表商品已返仓，重新增加库存需以实际可售入库为依据。

验收：未支付订单不能发货；发货后购买者可查物流信息；点击退款不能直接恢复未退回商品的可售库存。

### FR-08 订单售后与原路退款

- 售后登记必须关联原订单和具体商品，记录数量、金额或积分、原因及处理人。
- 退款范围不得超过原订单实付及剩余可退额度；重复受理、并发操作不得重复退款。
- 微信支付订单通过原支付渠道退款，记录渠道退款单号和实际结果；不允许以人工标记替代真实退款成功。
- 积分支付订单退回实际对应积分，形成关联原订单的退款流水；不在此流程中直接退现金。
- 首期支持按商品数量部分退款，保留已退、处理中及剩余可退数量，以及剩余履约情况，不能把整单直接标为全部退款。
- 已发货退货须关联退货单号、实际收货和验货结果；验货不通过时保留原因，不直接判定退款完成。
- 退款失败、处理中与已完成应分别展示；相关失败支持查询与补偿。
- 已发生代理奖励的来源订单退款时，需要提示并记录关联奖励冲回。

验收：微信付 100 元不能累计退 101 元；积分付 100 积分退款后只增加一次 100 积分；三件商品退一件后，另两件仍可履约，已退和处理中数量不会再次受理退款。

### FR-09 积分余额退款

- 首期由工作人员受理并核验原公司收款、可退余额及收款人信息，不开放自助提现。
- 同一笔可退积分不得重复申请或在退款处理中继续消费；用户能区分可用和处理中占用的积分。
- 记录申请、审核、实际退现金额、对应积分、退款凭证、操作人和最终结果。
- 确认实际退款成功后形成积分扣回记录；处理中保留占用，失败或驳回释放占用。
- 已消费且未因订单退款实际退回的积分不能申请退现金；普通订单退款实际退回且尚未再次消费的积分可以人工申请。
- 退款金额同时受当前可退积分、原公司收款剩余未退金额约束。按 1∶1 扣回对应积分，并保留原收款、订单积分退回和本次现金退款的关联依据。

验收：可用 1,000 积分，其中 600 积分进入退款处理后最多还能消费 400 积分；退款成功扣回 600，失败释放该占用。

### FR-10 代理奖励核算与结算记录（首期必做）

- 首期上线必须提供人工核算、人工结算及退款冲回的记录能力，不建设自动计算或自动打款引擎。
- 每笔记录包含奖励对象、来源业务、类型、金额、核算依据、记录人和结算情况。
- 类型仅限入驻奖励和店主订货收益：前者对应直接邀请人，后者对应来源店主的归属主理人，不逐层递推。
- 入驻奖励按新加入者身份使用店主、主理人两档固定金额，保存该次审核通过时适用的档位与金额；未配置金额不能用 0 或示例值代替。
- 店主订货收益使用来源订单各规格的成交单价、当时主理人价和实际数量人工核算，不含运费；微信付款和积分付款同规则。
- 登记时保存来源业务对应的奖励对象与归属依据，后续身份变化不把已确认来源奖励静默转给他人。
- 结算通过公司线下转账，记录实际收款人、支付时间、金额及凭证；不因登记奖励或结算计划就视为已付款。
- 来源退款时关联冲回记录：未支付部分减少待结算额；已付部分优先抵扣同一人后续应结算奖励，不足部分人工追回，保留未完成处理事项。
- 每笔抵扣关联原待追回记录和本次应结算奖励，记录实际抵扣额；抵扣不能超过未追回额或本次可抵扣额。实际转账金额与抵扣金额分别记录，防止重复扣回。
- 不将代理奖励直接计入订货积分余额。
- 人工登记允许关联适用规则及其文字依据，保留当次核算口径，后续规则调整不覆盖已有奖励记录。
- 奖励区分“尚未满足结算条件”和“可结算”；须核实对应商品收货完成、售后期结束且无待处理售后。入驻奖励还须核实相应入驻已审核通过和产品包收款交付，不因仅提交申请或公司收到转款就结算。
- 每月集中线下转账一次，登记所属结算月份、实际付款日和金额。未来抵扣只使用同一人符合条件的应结算奖励，不提前抵扣尚未具备结算资格的预估奖励。
- 来源订单有部分退款时，支持人工登记部分冲回及剩余奖励；同一来源、对象和奖励类型的重复记录应提示核对，防止重复结算。
- 订货收益冲回使用退货商品的原价差及退款数量；入驻奖励冲回使用原奖励金额与产品包货款退款比例，排除退运费金额；全部退款时冲回原奖励剩余全部金额。
- 品牌方能查询待结算、已结算、冲回、已抵扣、已追回和未收回差额；未实际收回的金额不能标记完成。
- 小程序“我的”提供本人奖励列表和详情，展示来源业务、金额、结算及冲回情况，必要时展示抵扣；不泄露无关人员订单和个人资料，不提供在线提现入口。

验收：本人可查询奖励，其他代理不能越权读取；已付奖励需收回 100 元、后续应结算 80 元时，人工抵扣 80 元后待追回剩余 20 元，不再转出该 80 元，也不把剩余 20 元标为已收回。金额仅为验收示例。

### FR-11 配置与后台操作

- 首期提供商品规格价格、身份权益、入驻说明、收款说明、客服、首页内容和固定配送规则的配置。
- 提供店主及主理人两档固定入驻奖励、售后期天数、每月结算日期的配置；保留修改记录与原业务适用值。配置能力不等于自动核算或自动转账。
- 配置保存前校验必填项和数值范围；生效时记录操作人、时间、变更前后值。
- 新配置适用于后续新业务，不自动改写已有订单、收款、积分和退款记录。
- 不建设通用公式编辑器、复杂审批平台或多层优惠叠加规则。
- 管理操作按账号授权，收款发积分、退款、身份及价格变更均可追溯。

验收：运营改价后，新下单使用新价，历史订单和已记账流水保持原值。

### FR-12 入驻产品包收款与交付

- 后台维护产品包名称、适用身份、明细、数量和货款，申请关联当时确定的产品包信息。
- 首期产品包仅采用公司转款，记录实际收款、付款人、金额、凭证和入驻申请；区分产品包货款与积分订货转款，不增加产品包微信收银入口。
- 记录对应商品的发货和售后，可复用首期已有的订单、物流及退款能力；不能只有审核通过记录而没有商品交付依据。
- 产品包付款不额外发积分。单笔资金不同时承担已交付产品包货款和未消费积分余额。
- 产品包退款由品牌方核验原公司收款后人工退回，记录凭证和实际结果，不通过积分返还产品包货款。
- 整包全部退款完成后撤销该次入驻取得的身份；部分退货由品牌方审核是否仍满足入驻条件。保留身份变更原因、关联申请、产品包退款及操作记录。
- 后续新订单使用实际有效身份价格；历史订单、积分和奖励不自动抹除或重算，相关奖励退款冲回按 FR-10 单独办理。
- 原型产品包金额仅为示例；具体价格及明细由品牌方维护。

验收：一笔 2,980 元产品包货款只形成对应的产品包收款和交付记录，不额外增加 2,980 积分；该金额仅为验收示例。

### 6.1 奖励计算与结算验收示例

本节金额和天数以已配置值为准，以下数值仅用于说明计算与验收，不作为实际经营参数。

| 项目 | 已确认计算口径 | 核验要求 |
| --- | --- | --- |
| 入驻奖励 | 根据新加入者身份读取店主或主理人固定档位金额 | 不再乘产品包价格比例，也不因邀请人身份再叠加奖励 |
| 店主订货收益 | 对各商品求和：数量×（原店主实际成交单价－当时主理人订货单价） | 仅商品货款，运费不计入；积分商品货款按 1∶1 计算 |
| 结算条件 | 收货完成、适用售后期结束、无待处理售后；入驻奖励还需对应入驻审核通过 | 不满足条件先列为未到结算期，不把登记记录当作可付款资格 |
| 实际付款 | 每月集中线下转账一次 | 记录月结批次或月份、收款人、抵扣额、实转金额及凭证 |
| 订货收益部分冲回 | 退货数量×该退货商品原单位价差 | 累计冲回不超过该来源原收益；保留未退商品对应收益 |
| 入驻奖励部分冲回 | 原入驻奖励×累计已退产品包货款÷原产品包货款，减此前已冲回额 | 不包含运费，不按最新档位计算；全部退款时补齐剩余冲回额 |

1. **订货价差**：店主商品成交价 100 元、当时主理人价 80 元，购买 3 件，运费 10 元。原收益为 60 元；微信或积分付款结果一致，运费不计收益。退其中 1 件时冲回 20 元，余下 40 元保留。
2. **入驻奖励冲回**：产品包原货款 1,000 元、原入驻奖励 200 元。第一次退货款 250 元，应累计冲回 50 元；再退 250 元时，再冲回 50 元。全部货款退完，原 200 元奖励须全部冲回。
3. **结算门槛**：商品已付款但尚未收货，或售后期尚未结束，或存在未处理售后，均不可实际结算；满足条件后进入对应月份的人工结算。
4. **历史价格**：原价差为每件 20 元，下单后将主理人价改为 70 元，原订单收益仍按 20 元单位价差核算，退款也使用原价差。

奖励金额精确到分，计算过程保留精度，登记结果按人民币两位小数四舍五入；累计冲回以原奖励为上限，全部退款时补齐尚未冲回余额，避免分次取整导致多收或少收。

## 7. 状态与一致性要求

| 业务 | 基本状态 | 关键限制 |
| --- | --- | --- |
| 入驻申请 | 待审核、通过、驳回 | 不得在条件未核实前自动开通身份 |
| 商品订单 | 待付款、待发货、已发货、已完成、已关闭 | 已付款不能当作未付款关闭；售后另行记录 |
| 支付 | 待支付、确认中、成功、失败或关闭 | 结果未明不重复付款，不发货 |
| 售后 | 已受理、待审核、驳回、待寄回或验货、待退款、退款处理中、退款完成 | 不需退货的业务跳过寄回；是否适用以售后规则为准 |
| 公司收款发积分 | 待核实、已核实待发放、已发放、已纠正 | 原收款与积分流水关联；已发放不可无痕覆盖 |
| 积分余额退款 | 待审核、处理中、成功、失败、驳回 | 积分占用、扣回和释放必须对应实际结果 |
| 奖励 | 未到结算期、可结算、已结算；另记冲回及处理情况 | 条件不满足不得实际结算；部分结算或冲回不丢失原始金额 |
| 产品包交付 | 待收款确认、已收款待发货、已发货、已完成；售后另记 | 收款、交付、入驻审核分别有依据，不重复发积分 |
| 代理身份 | 未开通、有效、已撤销 | 产品包全部退款触发该次身份撤销，历史业务记录保留 |
| 已付奖励收回 | 待收回、部分收回、已收回 | 以实际抵扣或追回为依据，不因登记冲回直接标为已收回 |

付款失败不自动使订单关闭；是否仍可支付以订单有效期和库存核验为准。订单取消、超时关闭后必须处理库存占用，并核查可能在途的支付结果；如发生关闭后的实际到账，应进入可查询的异常处理流程。

## 8. 数据与审计

首期至少保存：用户与代理档案、入驻审核、产品包及其收款交付、商品规格与价格、地址、订单及明细、支付、发货、售后、退款、公司收款、积分余额与流水、积分退款处理、奖励及核算结算冲回、配置及操作记录。

- 金额与积分统一明确单位和两位小数精度；积分不是现金支付流水。
- 订单保存成交快照，审计记录能定位实际操作账号。
- 原始公司收款、积分发放、订单支付、退款分别使用可追溯业务编号。
- 每笔积分变动均有来源、方向、数量和变动结果，不能只保留当前余额。
- 不物理删除业务记录。移除或停用按逻辑删除处理，正常查询过滤已删除数据，历史业务快照仍可查询。
- 若使用 MySQL，审计字段采用本项目约定的 `id`、`update_user_id`、`create_user_id`、`create_time`、`update_time`、`is_deleted`，不新增用户姓名审计字段。
- 涉及逻辑删除的唯一约束须允许按业务要求重新写入，不通过物理删除解决冲突。
- 付款、发积分、退款等失败记录业务编号、请求或追踪编号、失败原因和处理结果。需要重试或人工补偿的事项必须可查询；日志避免输出完整敏感个人信息。

## 9. 关键异常与用户提示

| 场景 | 首期处理要求 |
| --- | --- |
| 代理未收到积分 | 能查询收款是否核实、积分是否发放；展示客服入口，不因再次询问而重复发放 |
| 积分不足 | 展示可用余额，可改微信全额支付或查看转款说明 |
| 支付结果未明 | 展示确认中，查询原支付；不立即引导重复付款 |
| 商品价格、库存变化 | 付款前提示并重新确认，不能静默改金额 |
| 地址不配送 | 下单前说明，不让用户付款后才发现 |
| 退款处理中或失败 | 保留记录，展示真实状态，支持后台查询和补偿 |
| 误发积分 | 留存纠正依据，防止余额不足时强行扣成负数；由品牌方处理未解决差额 |
| 公司转款凭证不清楚 | 标记待核实，不凭截图直接认定到账 |

## 11. 上线验收清单

- [ ] 游客登录后按零售价微信付款，品牌方可发货，购买者可查看单号并确认收货。
- [ ] 店主和主理人分别按身份价格购买；支付方式不会改变同一身份的商品价格。
- [ ] 一笔公司实际到账 1,000 元只发一次 1,000.00 积分，收款与积分流水能对应。
- [ ] 积分订货只扣一次，余额不足、并发提交和重复通知不产生超扣。
- [ ] 微信支付关闭、失败、确认中和成功展示正确；不凭前端返回判定到账。
- [ ] 价格、数量、运费与实付一致；历史订单不受后续改价影响。
- [ ] 未付款取消、超时和支付竞争不会造成永久库存占用、超卖或已收款无记录。
- [ ] 未支付订单不能发货；退款处理中按受理范围控制发货。
- [ ] 微信退款真实退回微信，积分退款真实回到积分余额，均能追溯原交易。
- [ ] 积分余额退款占用、退款成功扣回、失败释放可验证，不能重复消费待退积分。
- [ ] 入驻审核、归属、发积分、发货、退款和改价可以定位操作账号。
- [ ] 奖励核算、实际结算及来源退款的部分或全部冲回均有记录，待处理差额可查询。
- [ ] 入驻奖励和店主订货收益对应正确对象，没有多层递推；公司线下转账结算可追溯收款人和凭证。
- [ ] 入驻奖励按新加入者身份的固定金额，订货收益按原商品价差和数量计算，运费不计收益；微信和积分规则一致。
- [ ] 未收货、售后期未结束或存在待处理售后的奖励不能结算；合格奖励按配置的月结日期人工转账并登记月份。
- [ ] 部分退款分别按原商品收益或产品包货款退款比例冲回；全部退款时补齐原奖励剩余冲回额，改价和改奖励档位不影响历史计算。
- [ ] 已付奖励抵扣后续应结算奖励后，实付与剩余待追回金额准确，不重复抵扣或超额抵扣。
- [ ] 代理只能查看自己的奖励来源、金额、结算及冲回记录，无在线提现入口。
- [ ] 已发货退货及按商品数量部分退款可处理，未退款商品继续履约，数量和金额不超退。
- [ ] 入驻产品包有收款和交付记录，其货款不额外增加积分。
- [ ] 产品包全部退款后撤销该次入驻身份，新订单使用当前有效身份；历史订单和积分记录保留，部分退货有身份审核结果。
- [ ] 普通订单退款退回的未消费积分可人工申请退现金，原收款累计现金退款不超额。
- [ ] 购买者不能查询或操作他人的地址、订单、钱包和售后记录。
- [ ] 手机端核心页面可读，顶部与底部操作区域不被微信界面遮挡。

上述验收是后续实现与测试目标；当前尚未开发，不表示已通过验证。
