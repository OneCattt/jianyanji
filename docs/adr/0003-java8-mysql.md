# 首期服务端改为 Java 8 与 MySQL 8

用户在项目上线前决定将服务端迁为 Java，以便使用熟悉的 Java 部署和运维方式。采用 Java 8、Spring Boot 2.7.18、JdbcTemplate、MySQL 8 和 Flyway；保留现有 HTTP 合同、原生小程序、Vue 管理后台和业务规则。部署形态为单个 JAR，生产运行不需要 Node 服务；Node 仅用于前端构建及本地命令。

迁移保留原 SQLite 单写事务的顺序语义：业务写事务先锁定 MySQL 的固定业务互斥行，嵌套服务共用同一事务。该选择简化首期库存、积分、退款与奖励之间的一致性验证，但会限制并行写入吞吐；今后需要提高吞吐时，应在并发回归保护下按订单和钱包等业务对象拆分锁。微信渠道网络操作放在数据库事务外，未决结果与补偿状态持久化。

旧 TypeScript 服务保留为迁移行为基准，不再是默认运行或生产入口。既有本地数据通过只读快照和空库原子导入迁移，原账号、权限、密码摘要、业务编号、审计记录与逻辑删除状态均保留。
