# 清欣简妍肌

当前交付任务 01：微信登录、有效购买身份、本人资料、品牌方后台账号与权限、操作记录。包含可直接导入的微信原生小程序、Vue 后台及购买端浏览器体验入口。

## 本地启动

推荐 Node.js 24 LTS，最低 22.13。无需 Java 或独立数据库服务。

```bash
npm ci
cp .env.example .env
npm run seed:demo
npm run dev
```

- 浏览器体验：<http://127.0.0.1:5173/>。
- 品牌方后台：<http://127.0.0.1:5173/admin>。
- API：<http://127.0.0.1:3100/api>。
- 本地后台演示账号：`admin`（全部首期账号权限）、`operator`（只查看用户）。本地密码均为 `Jianyanji-Local-2026!`。
- 浏览器底部“本地调试账号”可选择游客、已存在的店主或主理人。只有显式运行演示数据初始化才会创建这两类代理；选择一个不存在的调试账号仍然只创建游客。
- `.env`、SQLite 数据、构建产物、截图均不纳入 Git。演示初始化幂等，不覆盖已有账号、密码或身份。

## 微信原生小程序

1. 微信开发者工具导入 `miniprogram` 目录，正式联调将 `project.config.json` 中的 AppID 改为实际小程序 AppID。
2. 服务端 `.env` 填写 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`，密钥只放服务端。小程序通过 `wx.login` 获取临时 code，再由服务端调用微信换取 openid。
3. 真机联调将 `miniprogram/config.js` 的 `apiBase` 改为实际 HTTPS API 地址，并在小程序平台设置 request 合法域名。默认本机地址供开发工具使用。
4. 仅本地模拟体验时，可把小程序配置中的 `devAuth` 显式改为 `true`，同时保持服务端本地 `DEV_AUTH=true`；开发工具访问本机 HTTP 时按工具要求关闭本地合法域名校验。正式环境保持 `devAuth=false`。
5. 首页、商城空状态可匿名访问；“我的”登录后显示当前身份并保存昵称及联系电话。联系手机号为用户填写的联系资料，不等同微信认证手机号。

尚无商品及交易模块；商城是明确的准备中状态。代理开通由后续任务 07 提供，当前不提供自助改身份入口。

## 首次正式管理员

填写 `.env` 的 `ADMIN_USERNAME`、`ADMIN_PASSWORD`（至少 12 位），执行：

```bash
npm run bootstrap:admin
```

仅在没有启用的账号管理员时初始化，不覆盖现有管理员。之后由后台新增工作人员、分配权限、启停或移除账号。密码用随机盐 scrypt 摘要保存；后台使用 HttpOnly、SameSite=Strict 的 cookie 会话，生产环境增加 Secure。移除仅逻辑删除并保留历史，重新创建同名账号获得新的编号。

正式运行使用独立数据库文件，并配置 `NODE_ENV=production`、`DEV_AUTH=false`、实际微信参数及 HTTPS 同源入口；生产环境开启调试登录会拒绝启动。反向代理须保留外部 Host 和 Origin，后台写入校验同源。首次构建后可由同一服务托管页面：

```bash
npm run build
npm start
```

构建模式页面入口为服务端的 `/`、`/admin`，默认端口 3100。不要把本地演示数据库用作正式业务库。

## 技术与权限约定

- TypeScript + Express 5 服务端；Vue 3 + Vite 提供后台和浏览器购买端；微信端使用原生 JS/WXML/WXSS。
- SQLite 使用 Node 内置驱动，数据库默认 `data/jianyanji.sqlite`；结构初始化可重复执行，数据跨重启保留。当前交付不要求独立 MySQL 实例；未来实际使用 MySQL 时采用项目规定的审计字段与毫秒时间格式。
- 业务表均包含创建修改用户、创建修改时间和逻辑删除标记；正常查询过滤已删除记录，生效中的登录名和微信身份使用部分唯一索引，允许逻辑删除后重新创建。
- 购买身份仅为有效的 B 主理人、C 店主、D 游客；品牌方是后台功能授权体系。登录、修改个人资料、后台授权均不会自动授予购买优惠。
- 购买端仅访问本人资料；后台三项权限为 `staff:manage`、`users:read`、`audit:read`。前端隐藏无权限入口，服务端独立校验。
- 身份、停用状态和权限在每次请求时读取，避免已有令牌携带过时身份。停用或移除工作人员同时撤销旧会话，重新启用必须重新登录。
- 操作记录保留对象编号、操作者类型及编号、动作、结果、原因和请求编号。资料越权、功能越权、登录失败同样有记录；日志不保存密码、微信密钥或临时 code。
- 金额、商品、积分、代理审核等后续业务沿既有任务实施，不在本任务建立虚假业务入口。

接口和权限详见 [身份接口说明](docs/development/identity-api.md)，任务和证据详见 [01 实施记录](docs/development/01-implementation.md)。
